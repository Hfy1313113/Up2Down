# 系统架构

## 总体结构

```
浏览器 A ══ WebRTC DataChannel（画作 / 风格 / 开赛载荷，点对点）══ 浏览器 B/C/D
    │
    │  HTTP：前端静态资源（含风格包资源）
    └── WebSocket（控制面：成员 / 信令 / 保活 / 超时兜底）
              │
        Cloudflare Worker ── Durable Object「Room」按房间号路由
```

- **同一个 Worker 也是静态托管方**：`[assets]` 指向 `frontend/dist`，`/`、`/play`、`/about`、`/privacy`、`/terms`
  及其前端路由由它返回（SPA 回落），因此整站只有一个域名、一份部署，前端与控制面天然同源。

- **数据面**：`RTCDataChannel`（每对玩家一条，`ordered: true`）。网状拓扑，4 人 = 每端 3 条连接。
  画作提交、风格选择、开赛载荷等全部点对点传输，**不产生任何 Cloudflare 流量**。
- **控制面**：Worker 上的 WebSocket。承担五件事：房间成员表（含满员拒绝）、本轮状态
  （`round` / `roundSeq`，用于候场判定）、WebRTC 信令转发、保活（25s ping）、绘制阶段超时兜底。
  Worker 不保存画作，也不感知风格，出口流量为 KB 级。
- **降级**：某条 P2P 链路建连失败（对称 NAT / 公共 STUN 穿不透）时，该 peer 的游戏消息
  自动改走控制面 `relay` 定向转发，其余 peer 仍走 P2P；界面在大厅/等待屏显示
  「P2P × n · 兜底中转 × m」，用户可见但不需干预。

## 前端结构

- **Vite + React + TypeScript + Tailwind CSS**，纯静态产物，由同一个 Worker 的 `[assets]` 托管（也可单独挂 Pages）。
  样式全部由 JSX 上的 Tailwind 工具类决定，颜色只引用 CSS 变量（`bg-(--ui-accent)` 等），变量由当前风格包写入 `:root`；
  `index.css` 只在 `@layer base/components` 放基础与动画样式，不写元素级规则（未分层规则会压过工具类）。
- `src/router.ts` + `src/pages/`：极简路径路由（pushState）。`/` 首页、`/about`、`/privacy`、`/terms` 为带统一标题栏与页脚的静态页；`/play` 进入游戏阶段机。
- `src/game/`：纯算法，无 DOM 依赖——分部位识别（`recognize.ts`，含象鼻曲线分离）、速度公式（`metrics.ts`）、
  步态相位（`gait.ts`）、赛跑物理积分与碰撞动力学（`raceSim.ts`，含连点加速脉冲衰减、极限加速过载监测、连续超上限 3 秒甩下象背出局机制、冲撞/拌腿/美式截停/创飞交互，**不含随机数**）。可被单测直接驱动。
- `src/style/`：**风格包层**。`types.ts` 定义契约（材质槽位、附件、装饰物、环境、展台、UI 配色、音乐、音效），`validate.ts` 结构校验，`registry.ts` 用 `import.meta.glob` 自动发现 `packs/*/index.ts`，`materials.ts` 把材质描述解析成 three 材质（程序化纹理画到 Canvas、图片纹理走 loader、按描述缓存统一释放），`theme.ts` 写入 CSS 变量并记录本机偏好，`preload.ts` 预载图片与音乐文件。
- `src/audio/`：**音频层**。`context.ts` 全局唯一 `AudioContext` + BGM / SFX 两条总线，`settings.ts` 本机偏好，`sequencer.ts` 把程序化乐谱编译成事件并前瞻调度，`music.ts` 背景音乐播放器（文件优先、回落程序化、文件曲目逐遍播放并在结尾渐出/第二遍起渐入、压低），`sfx.ts` 音效预设库（风格包按事件选预设或文件）。
- `src/three/`：three.js 场景层。`elephantMesh.ts` 由识别模型生成 3D 大象及驭象师模型（双关节连杆按步态驱动，象鼻 / 象牙 / 扇耳 / 象毯，驭象师附件库按风格包清单挂载，连点挥鞭动力学与甩下象背的人象分离、四肢大风车失控抛飞姿态）；
  `environment.ts` 按风格包声明构建天空 / 雾 / 灯光 / 地面 / 跑道 / 栅栏 / 终点门 / 礼花筒 / 云朵，`props.ts` 装饰物库（棕榈、圆树、灌木、岩石、神庙、托拉纳门、彩旗、灯笼、路灯、旗帜、远山）；
  `raceScene.ts` 渲染赛道、俯瞰视角聚焦自身相机、第一人称自由转头环视、第二人称大象回眸目送驭象师特写、物理位移与冲线礼花筒粒子系统；`birthScene.ts` 渲染具象化展台（含大厅预览模式）。
- `src/state/game.ts`：阶段机 `lobby → draw → birth → waiting → race`、房主协调逻辑与风格同步。
- `src/net/transport.ts`：唯一网络出口，封装控制面与数据面的选择、去重、降级、重连。

## 关键设计决策

1. **客户端同算 + 房主权威结算**：赛跑模拟是不含随机数的纯函数（`raceSim.ts`），各端用同一套
   画作各自推演、各自渲染；但连点加速（`elephant_boost`）经网络到达对端有延迟、各端帧 `dt` 也不同，
   位置会有微小分叉，因此**名次不由各端自判**：房主端模拟结束时把 `ranking()` 结果以
   `race_result` 广播，所有客户端以该消息渲染同一份结算。非房主若本地先跑完则显示
   「等待房主结算」，超过 8s 未收到（房主掉线且未移交到自己）才退回本地名次兜底。
   服务器仍不参与仲裁，也不同步任何高频状态。
2. **房主客户端为协调者**：开赛判定、画作汇总、超时后组装 `race`、风格选择都由当前房主完成，
   服务器只提供成员表、本轮状态（`round` / `roundSeq`）与超时事件。开局后加入的成员是候场者，
   不参与本局判定与赛跑，在大厅等待「再来一局」。流程消息（`draw_phase` / `race` / `again` /
   `race_result` / `style`）只接受房主发出，传输层按到达通道标注 `_from` 供上层校验。
3. **房主选风格、全员同步**：房主在大厅切换风格即发 `style{id}`；`room_state` 变化时房主重发一次，
   让新进房者立即同步；`draw_phase.style` 与 `race.style` 再各携带一次兜底。各端收到即写入
   CSS 变量（界面即时换色）并预载该风格的图片与音乐文件，绘制阶段有 150s 窗口，开赛零等待。
   房主上次选择保存在本机 localStorage。
4. **风格包：声明式内容 + 机制解析**。风格包只描述「有什么」：每个材质槽位的颜色 / 程序化纹理配方 / 图片 URL，
   驭象师附件名清单，装饰物种类与数量，环境参数，UI 配色，音乐乐谱或文件，音效预设。
   机制层负责「怎么画 / 怎么放」：`MaterialResolver` 解析材质并按（描述 + 玩家色）缓存，
   `props.ts` 装饰库、`elephantMesh.ts` 附件库、`sfx.ts` 音效预设库、`sequencer.ts` 程序化音序器。
   `"$player"` 占位在解析时替换成该玩家的身份强调色，四位玩家各不相同。
   新增风格 = 新建 `src/style/packs/<id>/index.ts`，注册表自动发现，开发态校验失败直接抛错。
5. **速度由绘制几何决定**（`frontend/src/game/metrics.ts`）：
   `速度 = 步幅(∝腿长) × 步频(∝1/√腿长) × 比例效率(大腿:小腿≈1.05:1 最优) × 质量系数`，
   缺腿合成腿 `quality=0.7` 惩罚。象鼻 / 象牙 / 耳 / 尾只影响外观。
6. **固定步态**：所有大象共用同一 gallop 相位函数，动画只决定姿态，位移由速度公式积分——
   「算法固定，速度由画决定」。
7. **分部位识别**：腿部画布笔画按 x 排序取 4 条，膝关节取笔画转向最明显处；躯干为一条线，
   由髋部自动生成。头颈分离识别——端点离躯干前锚点最近（对锚点前方且更低的端点加罚，避免把象鼻当脖子）
   的笔画为脖子（两端点即脖子根/头端）；**象鼻为附加细节**：其余笔画中细长下垂、最低点明显低于头部其他笔画的一条
   分离为象鼻，重采样为鼻根→鼻尖 8 点曲线，没画则网格层程序化生成，其余 2D→3D 映射与原来一致；
   剩余笔画构成头点云（质心=头心），朝向=头心−脖子根单位向量，耳尖=短笔画顶端或长笔画
   上的尖锐上凸峰（最多 2 个，网格层据此生成扇形大耳）；屁股笔画按「离髋部群最大距离」分离臀线与尾巴，尾巴从尾根
   到尾尖重采样为 8 点曲线并求摆动松弛度。
8. **2D 主题走 CSS 变量**：风格包 `ui` 配色经 `theme.ts` 写入 `:root`，所有屏幕的工具类只引用变量，
   切换风格无需重渲染组件树；画布引导线的主题色也从变量读取。
9. **音乐内容解耦**：曲目既可以是音频文件也可以是程序化乐谱；文件缺失、404 或 SPA 回落返回 HTML 时解码失败，
   自动改用乐谱，比赛不受影响。内置曲目全部程序化原创，不依赖第三方录音。
10. **零安装参与**：玩家无需运行任何本地程序，前端静态托管 + P2P 直连即可开局。

## 数据流

```
join ──(控制面)──> joined（单播自身 id）+ room_state（全员：成员表 / 房主）
                    └─ 各端据成员表建立 WebRTC 网状连接（id 小者发 offer）
                    └─ 房主 ──数据面 style{id}──> 全员（成员变化时重发；大厅切换时即时发）
start（房主）──> 数据面 draw_phase{style}（各端本地倒计时、锁定本局风格、预载资源）
              └─ 控制面 phase_start（服务端启动 200s 超时兜底）
done（每人一次，携带 {legs,head,butt} 笔画）──> 数据面广播：各端记进度，房主存画作
全员 done（房主判定）或服务端 race_timeout ──> 房主广播 race{elephants[{id,name,strokes}], style}
赛中 elephant_boost / elephant_bucked_off（每人）──> 数据面广播：各端同步他人加速与出局状态
房主本地模拟结束 ──> 数据面广播 race_result{rank[]}：全员据此展示同一份结算
again（房主）──> 数据面广播 + 控制面复位：回大厅（风格保持）
```

消息协议详见 [API.md](API.md)。

## 已知约束

- 公共 STUN（`stun.l.google.com:19302`）在部分校园/企业网络下穿不透，此时自动走控制面兜底，
  延迟与流量略升但仍可玩；如需完全直连可在 `frontend/src/net/transport.ts` 的 `RTC_CONFIG`
  中补充自建 STUN/TURN。
- Durable Object 的内存房间状态随实例回收而消失，房间空置后成员自然清空。WebSocket 使用
  非休眠模式，房间有人期间 DO 持续活跃计费；朋友局规模下免费额度足够，规模化前应改为 Hibernation API。
- 绘制阶段总时限由服务端兜底（`signaling/src/index.ts` 的 `DRAW_TIMEOUT_MS = 200s`），
  每个部位 50s 由前端本地计时。
- 非房主端看到的他人位置是近似值（连点加速经网络到达有延迟），名次以房主广播的 `race_result` 为准；
  房主掉线且未移交到本端时，本端最多等待 8s 后用本地名次兜底。
- 控制面断线重连会拿到新的 pid，重连者在本轮内会被视为候场者；赛中断线的玩家需等下一局。
- 风格包音频文件随仓库提交：放在 `frontend/public/styles/<id>/music/`，与代码一起构建与部署；
  缺失时回落到风格包内置的程序化乐谱。
- 浏览器自动播放策略：音频上下文在首个用户手势（首页按钮、进入象限、按钮点击）时创建或恢复；
  若直接打开 `/play` 且尚未交互，背景音乐会在第一次点击后开始。
